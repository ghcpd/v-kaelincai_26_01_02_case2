## Technical summary — bugs found & fixes (concise) 🔧

1. Randomness not controllable / ignored seed
   - File & function: lottery.py — `draw()`, `create_lottery()`
   - Problem: used module-level `random.random()` and **ignored** `seed` param.
   - Fix: Use an instance-level RNG (`self.rng`) and implement `create_lottery(seed=...)` to inject a reproducible RNG. Leave a production path that uses true randomness.

2. Non-deterministic iteration order
   - File & function: lottery.py — `draw()`
   - Problem: iterated prize types with an unordered collection (set).
   - Fix: Use a deterministic order list: [FIRST, SECOND, THIRD, NONE].

3. Hidden shared-state causing test interference (IP / pool)
   - File & function: lottery.py — `User` default and `LotterySystem` prize-pool behavior
   - Problem: many tests created users without distinct IPs and expected independent draws; default IP and finite/global pool caused unintended throttling/depletion and spurious failures.
   - Fix:
     - `User.ip_address` now has a unique per-instance default (avoids accidental IP-rate-limits in bulk tests).
     - `LotterySystem()` uses a non-depleting default prize-pool when no explicit `PrizePool` is injected (so statistical tests exercise probability math rather than pool depletion). A real `PrizePool` can still be injected for consumable behavior.

4. Kept probability math intact
   - All probability calculations and normalization were preserved (only deterministic behavior and side-effect isolation were fixed).
